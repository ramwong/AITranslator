# AITranslator UI 重新設計（紙感）

日期：2026-10-31
狀態：定稿（經瀏覽器 mockup 逐項確認）
取代：2026-10-31-popup-layouts-design.md（該版已整輪 revert，主因「太悶、不好看」；本文件為完全重新設計，非增量修改）

## 目的與背景

上輪深色彈窗改版（`52f1752` revert）整輪退掉：低彩度深灰系層級差太小、沒有視覺錨點、觀感悶。本設計改走**紙感（paper/ink）淺色主題**，動機：

- 深色彈窗在 WinForms 有原生控制項漏光問題（捲軸、選取高亮），淺色主題天然免除
- 該 app 是「存在十幾秒的小浮動卡」，設計勝負是精緻感而非功能堆疊
- 使用者明確表態：深色「太多軟件用了」

## 彈窗左右版面修訂（2026-11-01，經 mockup 確認）

上下分段對長段/多段文字不友善（實測使用者回饋），彈窗改為**單一左右版面**（參考 Crow Translate；原三版面切換器與上下分段實作移除，不做切換選項）：

- **W3 左窄右寬**：原文欄寬 ＝ 表單寬的 **38%**（全高米色欄、右緣 1px 髮絲分隔線），譯文欄 **62%**（白紙墨字）；兩欄各自可捲
- 原文欄上緣列：**無小標**（「⧉ 複製原文」鈕本身已隱含「這裡是原文」，使用者決策移除「選取文字」標籤）＋右側 🔊 朗讀、⧉ 複製原文（幽靈鈕）
- **動作列按鈕位置互換：⚙ 左、📋 複製右**——複製位於右欄（譯文）正下方，空間語意「複製＝複製譯文」，避免誤解為複製原文（使用者決策）
- **動作列高度動態化**：列高 ＝ max(Theme.FooterHeight, 兩顆按鈕 PreferredSize 高 + 上下留白 + 髮絲線)——根治「按鈕仍稍被擋」的殘餘問題，不再依賴固定魔術高度
- **按鈕字級固定 12pt**：不隨 settings.FontSize 縮放（使用者決策：字級調大時按鈕不需跟著變大）
- **上下兩列結構**（使用者決策，原 Dock=Left 全高會把動作列擠進右欄成為右欄的一 row）：外層 2 row——上 row＝左右雙欄（`_contentRow`），下 row＝全寬狀態條＋動作列
- **預設尺寸**：`AppSettings.PopupWidth/Height` 預設改 **640×320**（舊 settings.json 已存值者沿用舊值，需手動調一次）
- 狀態條全寬（上下兩列結構修訂後＝表單寬）、兩級錯誤語意、no-activate 合約、複製/TTS 用原始字串契約——皆不變

## 決策歷程（皆經使用者以 mockup 確認）

1. 方向：**紙感閱讀卡**（棄：A 輕盈浮動卡——原文縮一行與 OCR 核對需求衝突；棄：C' 深色 2.0）
2. 彈窗版面：**雙卡片**——原文自帶內嵌面板，譯文在白紙上（棄：上下分段、譯文當主角＋原文收合）
3. 字體：**全微軟正黑**（棄：襯線變化——WinForms 可靠中文襯線僅新細明體，觀感不足；附帶 Noto 字型檔 10MB+ 不划算）
4. 點綴色：**靛青**（棄：墨黑為錨、暖赭——與錯誤色語意太近）
5. 設定表單：**快捷鍵優先排序** D2（棄：照現行欄位順序 D1）
6. 目標語言徽章：**不做**——目標語言由 prompt 自由定義（繁中／港式中／粵語文），任何固化標籤都不成立
7. 複製原文：**收進原文面板**，與 🔊 並列於面板上緣（footer 維持「複製譯文」唯一主鈕；OCR 原文不在選取區，複製原文是真需求）
8. 行為層沿線：上輪被 revert 的**行為接線**（原文送入彈窗、彈窗內 🔊／⚙ 按鈕、TTS 狀態顯示、複製原文的剪貼簿處理）經審查且通過測試，revert 主因是觀感——本設計沿用其作法為行為層、重畫皮膚，不重寫等價程式碼

間距 token：卡片圓角 10px、外內距 12–16px、動作列高約 36px（bug-fix round 修訂為 44px——實測 AutoSize 按鈕需 31px 完整高度，36px 帶高僅 23px 會把按鈕裁掉上下緣）、面板內距 10–12px（builder 微調）。

顯示層文字正規化（bug-fix round 2026-11-01）：Win32 EDIT 只渲染 CRLF——模型輸出 LF 行在彈窗不可見、複製出去正常，顯示前統一 \r\n；微軟正黑對 U+2019/U+2018 以全形寬度渲染（實測 25px vs ASCII 13px @12pt），原文框顯示層代換為 ASCII 撇號。正規化僅入顯示；剪貼簿與 TTS 一律使用原始字串。

字體 token：全文統一「Microsoft JhengHei」；字級沿用設定值（`FontSize`，預設 12pt），譯文字級 = 設定值 + 2pt 級距由 builder 定。英文與數字允許 Segoe UI fallback 併排。

## 彈窗（`PopupForm` 重繪）

行為完全沿用現有狀態機（no-activate、`WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW|WS_EX_TOPMOST`、16px 偏移 clamp、DismissHook、busy 流程、Disposal），本節只描述「皮膚」：

- **原文面板**：淺米內嵌卡（Panel 色），上緣小標「選取文字」（Caption 色、letter-spacing 感以 11px 字級近似），右上角兩顆幽靈鈕：🔊 朗讀、⧉ 複製原文——朗讀與複製原文都屬「原文」語意，放原文面板內；原文面板自身可捲（OCR 長文完整性優先，故原文縮一行方案被否）。原文為空時兩鈕禁用
- **譯文區**：無背景大字（Ink 色），視覺主角、可捲
- **動作列**（FooterBg 底 + 髮絲上緣線）：靛青實心「📋 複製」主鈕靠左；「⚙ 設定」幽靈鈕靠右；**無徽章**（目標語言徽章不做）
  - 複製＝複製**譯文**，無譯文時禁用（沿用）；複製成功即關閉彈窗（沿用）；「複製原文」不關閉彈窗（核對原文的情境多半還要看譯文）
  - 複製原文與複製譯文共用同一套剪貼簿獨佔（ExternalException）容錯
  - 朗讀進行中的狀態由既有 TTS 狀態機驅動，顯示於狀態條
- **狀態條**（動作列正上方、或動作列一體的左側區，builder 擇一實作最穩者）：獨立於譯文的細條，錯誤分兩級：
  - 忙碌（翻譯中／辨識中／TTS 初始化中）：深色呼吸點 + 文字（muted）
  - **暫時性提示（2500ms 自動關，沿用 toast 語意）**：未選取文字、選取文字超過上限、TTS 失敗
  - **持久性錯誤（不自動關關，需使用者關閉彈窗或下一步動作覆寫）**：LLM／HTTP／OCR 辨識失敗等 `result.Error` 類失敗（含「未取得翻譯內容」）——失敗原因必須看得完，不能 2.5 秒後蒸發
  - TTS：Loading → 「TTS 初始化中…」忙碌點；Speaking → 「朗讀中…」（無點，muted，至完成或停止）；朗讀中再按 🔊 即停止（沿用既有 toggle 語意）；彈窗按鈕發動的 TTS 失敗走狀態條、熱鍵發動的走原 toast 路徑（沿用）
- 過渡／無內容狀態（辨識中、純提示 toast）：一律畫完整紙感骨架（小標、空面板、動作列），只是原文面板空白、相關鈕禁用——不另開更小的卡
- ⚙ 點擊時若翻譯/辨識進行中，先放棄本次結果再開設定（沿用上輪作法）
- 捲軸：原生淺色捲軸即符合紙感，不做自繪
- 進場動畫：不要求（builder 可選做極短 fade；若 WinForms 實作成本高則跳過，屬 nice-to-have）

## 設定表單（`SettingsForm` 重排）

- 五個小節、排序 D2（快捷鍵優先）：**快捷鍵**（翻譯／朗讀 TTS／OCR）→ **彈窗外觀**（寬／高／字級）→ **翻譯**（Prompt 範本／模型名稱／API 網址／選取文字上限）→ **辨識 OCR**（模型名稱／「辨識模型直接翻譯」勾選）→ **其他**（開機自動啟動）
- 小節樣式：Caption 色小標 + 髮絲分隔線（TableLayoutPanel 跨欄列），非 GroupBox
- **快捷鍵點擊錄製**：**靜止態顯示現值**（如「Ctrl + Alt + E」，小字註記「點擊更改」，muted）；點擊進入錄製態（虛線框、以 Accent 色顯示偵測到的組合鍵），按下實際組合鍵即錄入，`Esc` 取消。錄製本身排除純修飾鍵；**錄到與另一熱鍵重複的組合鍵當場 inline 擋下**（提示並保持原值），不等按「儲存」才發現。格式驗證規則沿用（至少一修飾鍵 + 單字母或 F1-F12）
- **驗證 inline 化**：錯誤以欄位旁赭紅色標記（紅點 `!`）＋說明文字呈現，移除逐欄 `MessageBox`；按「儲存」時聚焦並滾動到第一個錯誤。存檔 IO 失敗仍維持一個警示（同一 inline 模式即可）
- 表單尺寸：維持 AutoSize/GrowAndShrink；當內容高於螢幕 WorkingArea 時 clamp 高度並啟用 AutoScroll（「滾動到第一個錯誤」在此模式下實作）
- 標題列維持系統淺色（紙感相容，不再需要上一版研究的 dark title bar P/Invoke）

## OCR「直接翻譯」模式的原文面板

`OcrTranslateInVision = true`（單次呼叫直接輸出譯文）時，既有流程拿不到辨識原文，原文面板會空白、「複製原文」無從作用。**裁定採用上輪已通過測試的合併 prompt 路徑**：此模式下改以「辨識 ＋ 翻譯」單次呼叫，要求模型回傳原文與譯文（參考被 revert 的 `6e06447` 合併 prompt 與 `a6610d7` 的 payload 邊界處理、及其測試），拆解後分別填入原文面板與譯文區。`OcrTranslateInVision = false`（兩次呼叫，預設）流程不變。此為唯一允許觸及 OCR 提示詞建構的改動。

## 框選 OCR（`RegionSelectorForm`）

選取矩 Accent 靛青高亮邊；遮簾（`#66000000`）與十字準星不變。僅此一項改動。

## 非目標 / 反目標

- 不做主題切換（淺色唯一）
- 不加語言選擇器、目標語言徽章、歷史紀錄
- 不改翻譯／OCR／TTS 狀態機的設計（行為接線沿用上輪作法）；設定檔 schema 不動（本次無新增欄位）。唯一例外：見「OCR『直接翻譯』模式」節的合併 prompt
- 不追求像素級還原 mockup 的圓角抗鋸齒——WinForms 內建圓角成本（Region 鋸齒或 layered window 重工）不值得，允許直角或 builder 擇低成本近似

## 交給 builder 的部分

- 狀態條的具體落點與高度、呼吸點動畫是否做（Timer 即可）
- 各表單 TableLayoutPanel 的列高與彈性
- 快捷鍵錄製控制項的實作（`KeyDown` 攔截 + `PreviewKeyDown` 抑制 Tab 逸出等）
- ErrorProvider 或自繪標記的擇一
- 彈窗譯文與設定的字級換算細節

## 驗收線

- 現有測試全數通過（基準為 main 現況；新主題色票類如為純常數類可補單測，非必要）
- 彈窗：翻譯、OCR、TTS、錯誤 toast、點外關閉、Esc 全流程手測不回歸
- 設定：錄製快捷鍵、重複鍵驗證、存檔、開機啟動同步不回歸
