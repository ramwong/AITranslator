# 彈窗版面模式與設定按鈕——設計文件

日期：2026-10-31
狀態：已由使用者於瀏覽器 mockup 確認（三輪迭代，final-v3）

## 背景與動機

彈窗目前只有一種版面（譯文 + 底部複製鈕，淺色系統配色），使用者無法對照原文；
且 TTS 只有熱鍵，設定入口又只在系統匣，不知道在 tray 的使用者找不到。

## 需求（使用者原文決策）

1. 彈窗提供三種版面，於設定頁選擇：
   - **① 左右分欄（預設）**：左欄原文（左下「複製」「朗讀」按鈕區），右欄譯文（右下「複製」）。
   - **② 上下分段**：上區原文（右上「複製」「朗讀」），下區譯文（右下「複製」、「⚙ 設定」）。
   - **③ 純譯文**：不顯示原文，上邊譯文，底部「複製」。
2. 版面①② **同時適用於** Ctrl+Alt+E 剪貼簿翻譯與 OCR 框選翻譯（使用者已確認）。
3. **省 token**：設定為「不顯示原文」（版面③）時，OCR 不得回傳原文；
   顯示原文時則要拿回原文。
4. 新增 **⚙ 設定按鈕**於彈窗內（使用者未必知道入口在系統匣）。
   擺法經 mockup 三輪收斂為 **A + 微調**：
   - 版面①③：譯文區按鈕列「📋 複製」靠左、「⚙ 設定」靠右（左右撐開）。
   - 版面②：譯文列「📋 複製、⚙ 設定」兩顆「成組」靠右（⚙ 仍最右；同原文列兩顆相鄰的節奏）。
   - 三種版面共通規則：譯文列複製最左、設定最右（除版面②為成組靠右）。
   - 版面①左欄：「📋 複製」最左、「🔊 朗讀」最右（同構撐開；使用者指定朗讀靠右）。
   - 版面②上區：「📋 複製、🔊 朗讀」成組靠右。
5. **TTS 按鈕朗讀「原文」**（使用者已確認，不朗讀譯文）。
6. 按鈕帶文字（📋 複製／🔊 朗讀／⚙ 設定），統一按鈕大小。
7. 配色由實作者決定（使用者授權）。決定值見下。

## 我代決的細節（審查時請確認合理性）

- 配色（深色）：
  - 彈窗底色 `#1E1F24`；分隔線 `#3A3D45`；按鈕底 `#2A2C33`、邊框 `#3A3D45`；
  - 原文 `#9BA7B8`（灰藍，次級）；譯文/主要文字 `#F2F4F8`（近白，高對比）；
  - 錯誤訊息 `#D07A6A`；成功/就緒狀態語不需特別配色（沿用主要文字色），
    翻譯中/辨識中狀態文字沿用次要灰藍。
- 新設定 `PopupLayout`（enum：`Split` / `Stack` / `TranslationOnly`，預設 `Split`），
  隨 `AppSettings` JSON 一併存取；設定頁用 `ComboBox`（三選一），值變更後
  `OnSettingsChanged` 既有 `DiscardPopup()` 路徑會以新設定重建彈窗（彈窗建構子依版面配置）。
- 彈窗尺寸沿用現有 `PopupWidth`/`PopupHeight`（整個視窗），三種版面皆不另立尺寸參數。
- ⚙ 設定按鈕行為：點下 → 關閉彈窗 → 開啟設定對話框（既有 `ShowSettings()`）。
  彈窗為 no-activate 視窗但按鈕可收到點擊；設定為強制回應視窗會取得焦點。
- 「朗讀」按鈕行為：等同 TTS 熱鍵但跳過剪貼簿擷取，直接以「彈窗內的原文」
  走既有 TTS 狀態機（NotLoaded→EnsureLoaded、Ready→Toggle、Failed→toast 失敗原因）。
- 按鈕禁用規則：複製/朗讀鈕在對應文字為空或尚未取得前禁用；⚙ 永遠可用。
- 原文為空字串（例如 OCR 未辨識到文字）時仍走既有 toast 提示，原文區留空。

## OCR「拿回原文」的取得策略（token 經濟）

- **兩次呼叫模式**（`OcrTranslateInVision=false`）：辨識步驟本來就會輸出原文，
  直接沿用為顯示用原文——零額外成本。
- **單次呼叫模式**（`OcrTranslateInVision=true`）＋版面①②：
  改用「一次輸出原文＋譯文」的提示詞（新增常數，格式：原文、`\n---\n` 分隔、譯文），
  一次影像呼叫同時拿到兩者（比發第二次影像呼叫省得多）。解析時若分隔符缺席
  或解析失敗，整段輸出視為譯文、原文留空（降級不擋流程）。
- **單次呼叫模式**＋版面③：提示詞與流程完全不變（今天既有的
  `RecognizeAndTranslateAsync` 路徑）。
- 剪貼簿翻譯路徑：原文就地可得，無額外請求。

## 審查後補上的決策

- **TTS 狀態不打斷彈窗內容**（使用者決定）：彈窗內點「朗讀」時，TTS 初始化中／失敗等狀態
  以「按鈕區狀態列」短暫顯示（不覆蓋兩個文字區、不觸發 toast、不自動關窗）；
  失敗訊息以錯誤色顯示在該狀態列。點「朗讀」**不關閉**彈窗。Ready 之後開始朗讀的
  轉移與熱鍵流程一致（靜默）。
- **原文顯示時機**（實作者決定）：一拿到就顯示——剪貼簿路徑在「翻譯中…」階段即放入
  原文；兩次呼叫 OCR 於辨識完成後先放原文，翻譯完成後再放譯文；單次（合併）呼叫做完
  一次呼叫後原文譯文同時出現。
- **合併提示詞尊重範本**（實作者決定）：顯示原文版面的單次呼叫用新常數組成
  「原樣輸出全部文字 + `---` 分隔 + 翻譯」，其中翻譯那一半仍由使用者
  `PromptTemplate` 組成（客製範本不會被硬編碼蓋掉）。
- **TTS 按鈕不套 MaxTextLength 預檢**（實作者決定）：彈窗內的原文在進彈窗前都已
  過長度檢查（剪貼簿路徑、兩次呼叫模式）；合併呼叫情境的原文雖無預檢，但 TTS 為
  本地朗讀、無 API 成本，不攔截。
- **錯誤色範圍**（實作者決定）：凡透過 `SetText` 送達的失敗訊息（LLM/HTTP 錯誤、
  「未取得翻譯內容」）皆以錯誤色顯示；toast 維持現行行為與樣式。

## 介面變更草案（供寫計畫參考，非逐字 spec）

- `PopupForm`：
  - 建構子依 `settings.PopupLayout` 配置三種版面（共用深色樣式常數集中一處）。
  - `ShowTranslation` 增加選讀參數帶原文；`SetText` 增加選讀參數標示是否為錯誤訊息
    （錯誤以錯誤色顯示）。
  - 公開事件：`TtsRequested`（帶原文）、`SettingsRequested`；AppController 訂閱。
  - 原文/譯文皆為多行唯讀 TextBox（既有 Label 量測弱點的結論沿用）。
- `AppController`：`ShowTranslation`/`SetText` 呼叫點依 `PopupLayout` 與拿到的原文
  補上 source 參數；OCR 單次呼叫模式於顯示原文版面改走新提示詞；
  新增「以指定文字觸發 TTS」的共用路徑；訂閱彈窗新事件。
- `SettingsForm`：新增「彈窗版面」下拉欄位。
- 已知延後項不變（如「翻譯中按 OCR → ESC 致彈窗殘留」）。

## 目標 / 非目標

- 目標：三種版面、設定入口進彈窗、TTS 按鈕、深色配色、OCR 不多花 token。
- 非目標：不動 TTS 引擎與狀態機本身、不動熱鍵註冊、不做淺色主題切換、
  不做彈窗尺寸隨版面自動變換、不動 toast 文案與時序。
- 反目標：不允許「顯示原文但多發一次影像請求」的省 token 破口
  （版面③的單次呼叫不得改為雙請求）。
